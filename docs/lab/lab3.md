
# 飞机大战游戏系统重构项目计划书 —— 阶段三：策略模式应用

## 一、 项目概述
* **项目背景**：在“飞机大战”游戏系统的持续迭代中，飞机的射击行为呈现出高度的多样性与动态性。为了解决传统继承或多重选择判断带来的代码冗余、维护困难以及违反“开闭原则”等问题，本阶段将引入**策略模式（Strategy Pattern）**进行底层架构重构。
* **核心目标**：实现弹道算法与飞机业务逻辑的解耦，支持火力策略的灵活扩展与运行时的动态切换，并在此基础上丰富游戏元素（新增Boss机、道具效果等）。
* **面向对象原则体现**：封装变化点、面向接口编程、多用对象组合（Composition）少用继承（Inheritance）。

## 二、 开发环境与技术栈
* **IDE 工具**：IntelliJ IDEA 2025.3
* **开发语言**：Java OpenJDK 25
* **核心技术**：面向对象设计、UML建模、策略模式（Strategy Pattern）

## 三、 核心需求与设计任务（内容目标）

### 1. 架构设计与建模 (UML)
* **设计任务**：采用策略模式重构弹道系统。
  * **抽象策略（Strategy）**：定义统一的射击行为接口（如 `ShootStrategy`）。
  * **具体策略（ConcreteStrategy）**：将具体的弹道算法封装为独立的类（不发射、单排直射、双排直射、散射、环射）。
  * **上下文（Context）**：各类飞机实体（英雄机、敌机）作为上下文，内部维护一个对策略接口的引用，通过组合的方式调用射击行为。
* **交付目标**：绘制规范的 UML 类图，明确标注设计模式名称、类名、属性与方法。

### 2. 弹道与机型业务逻辑实现
系统需支持 5 种敌机与 1 种英雄机的特定发射逻辑：

| 飞机类型 | 默认弹道策略 | 具体弹道表现 |
| :--- | :--- | :--- |
| **普通敌机** | 不发射策略 | 无子弹生成 |
| **精英敌机** | 单排直射策略 | 单线直线射击 |
| **精锐敌机** | 双排直射策略 | 双线直线射击 |
| **王牌敌机** | 散射策略 | 单次同时发射 3 颗子弹，呈扇形/发散状 |
| **Boss敌机** | 环射策略 | 单次同时发射 20 颗子弹，呈环形向四周发散 |
| **英雄机** | 直射策略 (默认) | 获取道具后可动态切换策略 |

### 3. 游戏机制迭代更新 (Checklist 落地)
* **敌机生成机制**：
  * 游戏界面需正常循环随机生成 5 种敌机。
  * **Boss触发条件**：当玩家得分达到设定的指定阈值时，触发生成 Boss 敌机。
  * **唯一性限制**：同一时间内屏幕上最多只能存在 1 台 Boss 敌机。
* **Boss敌机特殊行为**：
  * **移动**：悬浮于游戏界面上方，仅执行左右移动，**不可向下移动**。
  * **攻击**：执行环射弹道攻击。
  * **阵亡掉落**：被击毁时，随机掉落 3 个道具（道具类型无限制）。
* **道具效果生效机制**：
  * **火力道具**：英雄机触碰后，当前射击策略动态切换为**散射弹道**。
  * **超级火力道具**：英雄机触碰后，当前射击策略动态切换为**环射弹道**。
  * **炸弹 / 冰冻道具**：本阶段不要求实现实际游戏画面效果，仅需在控制台输出对应的“生效提示信息”即可。

## 四、 项目约束与注意事项 (Constraints)

1. **多线程功能豁免**：本次实验暂未涉及多线程的开发实现。因此，英雄机吃下火力道具切换弹道后，**暂不需要实现“火力自动恢复/超时失效”的功能**（该状态恢复功能将在实验五中通过多线程完善）。
2. **重构原则**：必须彻底废弃在原有飞机类内部编写大量 `if-else` 或直接重写射击方法的实现方式，必须通过给 Context 注入具体的 Strategy 对象来实现多态。
3. **独立性**：策略类的代码应只包含弹道计算逻辑，使得算法对象能够完全相互替换，且不影响使用该算法的客户端（飞机类）。
